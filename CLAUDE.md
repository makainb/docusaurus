This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal Chinese-language content site (藏鲸阁) built with Docusaurus 3.10.2 + React 19, deployed to https://makainb.com via GitHub Pages. Content is predominantly Chinese prose: architecture docs for the "Matrix" frontend framework, weekly work reports (周报), rap lyrics, and a few standalone pages.

## Commands

CI uses npm (`package-lock.json`); a `pnpm-lock.yaml` also exists. Commands work with either.

- `npm start` — dev server on http://localhost:3000 (`docusaurus start --host 0.0.0.0 --port 3000`)
- `npm run build` — production build to `build/`; the closest thing to a test — run it after changing config, sidebars, or adding/moving docs
- `npm run serve` — serve the built site locally
- `npm run clear` — clear Docusaurus cache; needed when config/plugin changes don't take effect
- `npm run swizzle` — eject theme components for customization
- `npm run write-heading-ids` — auto-add heading IDs

There is no test suite, linter, or formatter configured.

## Deployment

- Push to `main` → `.github/workflows/deploy.yml` builds with Node 20 and deploys to GitHub Pages (custom domain makainb.com).
- PR to `main` → `.github/workflows/test-deploy.yml` runs a build-only check (Node 18).
- `npm run deploy` exists but is not the real path; deployment happens via the Actions workflow.
- `onBrokenLinks` / `onBrokenMarkdownLinks` are `"warn"` — broken links don't fail the build, so scan build output for warnings.

## Content architecture

Three-tier writing workflow:

1. `draft/` — top-level staging area, **not part of the Docusaurus build** (it is not a docs/blog content dir). Holds unfinished material organized by year (`draft/2026/`) or topic (`draft/SpringSecurity/`). Publish by moving files into `docs/`.
2. `docs/` — published docs. Only two sidebar groups are live (see `sidebars.js`):
   - `matrixFrontend` → `docs/08-Matrix/frontend/` — the Matrix 前端架构 doc set
   - `rapSidebar` → `docs/rap/` — 说唱 lyrics
3. `blog/` — 周报 under `blog/2026/YYYY-MM-DD-NNN.md`; rendered at `/blog` as "周报汇总", all posts listed in the sidebar, 10 per page, RSS/Atom feed enabled.

Standalone pages in `src/pages/`: `index.js` (typewriter-effect homepage), `tools.md` (兵器谱, `/tools`), `about.md` (`/about`).

### Adding a new doc section

Sidebars and navbar are coupled and live in config, not the filesystem:

- `sidebars.js` exports a map of `[{type: 'autogenerated', dirName: '...'}]`. Many sidebars (springSidebar, csSidebar, toolsSidebar, ...) are kept commented out — that's the template for re-adding a section.
- `docusaurus.config.js` → `themeConfig.navbar.items` needs a matching `{type: 'docSidebar', sidebarId: ...}` entry (commented-out examples are kept there too). A doc tree with no sidebar + navbar entry is unreachable.
- Numeric prefixes order entries and are stripped from URLs and sidebar labels: `docs/08-Matrix/frontend/intro.md` → `/docs/Matrix/frontend/intro`, and files like `0100-start.md` sort by prefix.

### Frontmatter conventions

- Categories: `_category_.json` per directory (`label`, `position`, often `link: {type: 'generated-index', description}`).
- Rap docs: pinyin `id` (e.g. `id: yanzou`), `date`, `sidebar_position`.
- Outline/scaffold files (currently the `docs/08-Matrix/*.md` roots) carry `draft: true` (excluded from production builds) + `sidebar_class_name: hidden-sidebar-item` (marker class; not defined in CSS).

## Markdown capabilities

Configured identically for docs, blog, and pages in `docusaurus.config.js`:

- KaTeX math: `$inline$` / `$$block$$` via remark-math + rehype-katex.
- `remark-breaks`: single newlines become `<br>` — meaningful for Chinese prose and lyrics.
- Mermaid diagrams: ` ```mermaid ` fences (`@docusaurus/theme-mermaid`).
- Prism with `java`/`json` extra languages; custom magic comments: `highlight-next-line`, `highlight-add-line`, `highlight-update-line`, `highlight-error-line` (each also has `-start`/`-end` block variants) — used to mark added/updated/error lines in code samples.

## Theme

- `src/css/custom.css` — global overrides: Sarasa Gothic webfont, reduced font scale, homepage-specific navbar styling (`.home-page-custom-style`, paired with `src/pages/index.js`).
- The site is Chinese-only (`zh-Hans` is the default and sole locale) — write site content in Chinese.
